# WP-03 requests (film production)

## For WP-06 (road / player) — gold clouds of `road-works` (supersedes the earlier "capsule" and "half-ellipse" notes)
- **Shape** (`film-manifest.endBands` / `endBandsPortrait`): the film ends on **three gold すやり霞 clouds built
  from seven tiers** (landscape and portrait each). Every entry is one tier `{ y, h, x0, x1 }`, normalised to the
  frame (y down): top edge `y`, height `h`, extreme ends `x0 … x1` (tips included; ends beyond the frame lie wholly
  off-frame). Tiers that overlap vertically belong to one cloud (entries 1–2, 3–5, 6–7); the stepped ends of
  overlapping tiers are what makes them read as Rinpa clouds, not bars — please keep all of them.
- **Ends taper to a spear tip** (verification pass, 2026-10-26 — the earlier long half-ellipse ends read as UI
  pills): for a pixel at distance `d` (px) from the nearer end, `t = clamp(d / L, 0, 1)` with
  `L = min(taper·h·H, (x1 − x0)·W / 2)`, `s = sin(πt/2)^power`; the tip sits at `y + apex·h`, the top edge at
  `(y + apex·h) − apex·h·s`, the bottom edge at `(y + apex·h) + (1 − apex)·h·s` (`taper 3.6, apex 0.38,
  power 0.7` in `src/film/scene/end-bands.json`). **Use `src/film/scene/end-band-path.ts`** (pure, DOM-free, no
  three): `endBandPath(tier, W, H)` returns the SVG path for a `viewBox="0 0 W H"` matching the stage, and
  `END_TIERS_LANDSCAPE / END_TIERS_PORTRAIT / END_GOLD` are exported too. `tools/film/verify.mjs` checks the last
  decoded frame against exactly this edge function (every differing pixel within 1 % of the frame height).
- **Colour**: plate 8 at **50 %** over paper = `#FBD78D` (day) — the P_8 tint of the film palette; in CSS
  `color-mix(in srgb, var(--plate-8) 50%, var(--paper))` (use the day values of both tokens, or the hex, so the
  bands match the video; the earlier 75 % `#FDC454` is retired). Flat, crisp edges, no blur/blend. The rest of the
  last frame is plain paper `#F7FCFE`. At night the film is under the 22 % lapis veil, so the DOM bands should be
  drawn with the same veil on top (or pre-mixed) to stay continuous.
- **Motion in the film's last 0.7 s**: the clouds rise from below the frame while drifting right → left and settle
  exactly on the last frame (zero velocity), so the DOM bands continue the right → left drift of §2.2.
- **Caption zones**: every landscape rest frame keeps the right ~30 % as calm paper — a mist bank of broad
  すやり霞 tiers in front of the diorama (their stepped ends sit between 57 % and 77 % of the frame width); portrait
  rest frames keep the top ~30 % calm (Hara portrait: the pink sky above the key-line frame, whose top edge
  sits at 43 % of the frame height). Captions on opaque paper plates sit on these zones without hiding the scene.
  Portrait: the fully calm paper reaches 27–32 % of the frame height, so a portrait caption longer than that
  covers the top of the diorama — keep portrait captions to year/station/role/headline (DESIGN: top 30 svh).
- **Top of the film / chrome** (WP-04, WP-06): the desktop chrome (document bar + ruler, 60 px; left ruler; status
  bar) lies over the film stage, and `object-fit: cover` crops a 16:10 stage ≈ 5 % a side. The film now keeps its
  key content inside that margin: Hara's rest framing was zoomed out so Fuji's peak sits at 11.5 % of the frame
  height and breaks the key-line frame at 16.5 % (frame sides inset 9 % of the width, bottom 6 %) — at 1440 × 900
  the peak is at ≈ 104 px, clear of the 60 px bar + ruler. Please do not let chrome or caption plates cover more
  than the top 8 % of the stage (the ja caption plate starts at 12 % per §6.3, which is fine).
- **Crossings**: between stations the frame is briefly all paper with two (portrait: three) stepped spear-ended
  clouds in the 25 % tint of the plate that is about to be printed (green before Hakone, grey before Mishima, pink before
  Hara, pale blue before Shimada, Prussian blue before Okazaki, dull grey before Shōno). Chapter captions can
  cross-fade there.
- **Rest frames = round(rest × fps)**: landscape 0, 66, 138, 207, 276, 345, 414; portrait 0, 53, 110, 166, 221,
  276, 331 (4.6 s and 13.8 s fall *inside* portrait frames 110 and 331, so `floor` would be wrong for 2.2 / 6.9 /
  9.2 s and `ceil` for 4.6 / 13.8 s). Those exact frames are the forced IDR frames of each encode and the stills.
  GOP: keyframes never more than 8 frames apart (a forced IDR restarts x264's 8-frame cadence; scene cuts add a
  few more), verified by `tools/film/verify.mjs`.
- Film colour: video and stills are tagged BT.709 limited range; the paper of the film is exactly `--paper`
  (#F7FCFE) in the master (±2 after 4:2:0 encoding).

## For WP-11 (integration)
- README "Commands": the film pipeline order is `npm run film:plates` (or `python3 -I tools/film/plates.py
  <station> [--meta]` for one station / framing only) → `node tools/film/traveller.mjs` →
  `flock .locks/browser.lock npm run film:capture -- --variant landscape --out assets-src/film/master-landscape.mp4`
  (and portrait) → `npm run film:encode` (the script takes the ffmpeg lock itself) → `npm run film:publish` →
  `flock .locks/browser.lock node tools/film/verify.mjs --content --determinism`.
  `tools/film/capture.mjs` starts its own Vite dev server on 5173 (`--strictPort`) when none answers; a capture
  survives a dev-server reload (it reopens the page and repeats the batch — frames are deterministic).
- `.gitignore` already ignores `assets-src/film/master-*` and `build/film/`; the generated plates
  (`assets-src/film/plates/**`, ≈ 6 MB of PNG-8) and `assets-src/film/traveller.png` are inputs of the capture and
  can be committed or regenerated (`npm run film:plates`, ≈ 15 min for all seven stations).
