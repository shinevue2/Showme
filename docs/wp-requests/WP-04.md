# WP-04 requests (chrome — the 版下 workbench): input for WP-11

Everything in `src/chrome/**` is implemented (DESIGN §4). The items below are what other packages need to know or
do so the chrome reads their sections correctly. Nothing here blocks a build.

## R1 · WP-11 (fonts, after content freeze): new chrome strings
`src/chrome/strings.ts` now carries every chrome label in ja/en/zh (Layers, Separations, Info sheet, Settings,
Glossary filter, Peek, mobile toolbar, CV headings, ruler units 寸 尺 間 里, 百二十六里 / 一百二十六里, 裏目 / 里目 …).
`scripts/fonts/fetch-fonts.mjs` already reads `strings[lang]` of this module: re-run `npm run fonts` so the body
slices include the new kanji (e.g. 転輪排字架, 摺, 裏目, 間, 里, 绘制, 调速器). Until then a few chrome glyphs fall back
to the system CJK face.

## R2 · WP-06 (road): film hooks the chrome reads
- `ctx.chrome.setRulerYears(p)` while the film scrubs (p = 0..1 across the section) and `setRulerYears(null)` when the
  section is left — the top ruler then reads 2018 → 2026 right to left with a 躑躅 marker at p (verified with the stub).
- Keep writing the current chapter to `#road[data-chapter="N"]` (the stub does): the Layers panel marks the chapter
  sub-layer and the outline view labels its crossed box `keyframe ch-N`.
- Info panel, film block: the variant is matched from `#road video.currentSrc` against `film-manifest` variants and the
  frame is `round(currentTime × fps)`. Push seek durations in **ms** to `debugFilm.seeks` (core/debug) so Info can show
  mean / p95; optionally set `debugFilm.plan = { variant, tier }` for the stills / static tiers (no `<video>`).
- `ctx.print.ink(n)` per chapter and `ink(8)` at the outro, as the stub does (Separations fills the plate rows with
  the registration snap and today's print gains the plate).

## R3 · all section WPs: eyes, separations, selection, cursors
- **Layers eye on a section** = `stage.pause('eye:<id>')` (view parks, poster shows) + `[data-eye="off"]` on the
  `<section>` + a `document` event `hanmoto:eye` `{ section, visible }`. Chrome CSS pauses CSS animations inside the
  section and hides `.plate-layer` elements and the 間 band's children. Sections with JS-driven 2D motion (SVG
  draws, GSAP tweens, the film) should stop it on that event / attribute and resume on `visible: true`.
  Choice is kept in `sessionStorage['hanmoto.eyes']`.
- **Separations**: decorative colour layers must carry `data-plate="N"` and be `aria-hidden="true"`, `.plate-layer`
  or SVG descendants, so `html[data-sep-off~="N"]` (WP-00 motion.css) hides them; text never carries a plate.
- **Selection boxes** hover anything with `[data-select]` (headings, figures, metric numbers, view placeholders) and
  read the section's `--layer` (layout.css). Put `data-select` on the elements a designer would want to inspect.
- **Cursors**: add `.cur-gouge | .cur-baren | .cur-hand | .cur-direct | .cur-rake | .cur-brush | .cur-seal`
  (`src/chrome/cursors.css`, WP-02 PNGs + hotspots); coarse pointers keep the platform cursor.
- **Outline view** (`html[data-view="outline"]`) is handled by chrome CSS + the stage; views implement
  `setOutline(on)` (wireframe/edges). Figures need `<picture data-file>` (render helpers already do this).

## R5 · WP-10 (colophon): today's print API
`import { renderPrint, printBlob, downloadPrint } from '../../chrome/print-compositor'` (import only).
`renderPrint(canvas, widthPx)` draws at `widthPx` CSS px (height = ⌊w × 1824 / 1240⌋: 120 → 176, 620 → 912,
1240 → 1824) from `ctx.print` (the chrome binds it; it falls back to `window.__hanmoto.ctx`); `printBlob()` returns
the full-size PNG (1240 × 1824, 620 × 912 on coarse pointers); `downloadPrint()` saves it. The compositor redraws only
when called: re-call it on `ctx.print.on('ink' | 'hide' | 'marbling' | 'seal')`. Order follows WP-02 R3 (plates 2–7
multiply, gold source-over, marbling in the cartouche, key block on top, name, seal). Deviation, deliberate: the
paper ground is always the day 胡粉 #FFFFFB — the print is an artwork and is never inverted at night (§3.6).

## R6 · WP-11: CV PDFs from the print stylesheet
`src/chrome/print.css` prints a dedicated `.cv-sheet` (rendered by `src/chrome/render.ts` on main pages, hidden on
screen) as **two A4 pages** in all three languages (verified: ja/en/zh = 2 pages each). Suggested
`scripts/build-cv.mjs`: open `{'' | 'en/' | 'zh/'}?proof=1` on `vite preview`, `await document.fonts.ready`,
`page.emulateMedia({ media: 'print' })`, `page.pdf({ format: 'A4', printBackground: true, preferCSSPageSize: true })`
→ `public/cv/cv-{ja,en,zh}.pdf`. Case pages print their article plainly.

## R8 · WP-00 (information): position restore in dev
In `npm run dev` the CSS is injected by JS, so `BOOT_BODY` restores `hanmoto.pos` against an unstyled layout and
lands sections off (measured: works → achievements). In the build the stylesheet is render-blocking and the restore
is correct. No change needed unless dev parity matters.

## Verification pass (WP-04 verifier, 2026-10-26)

All WP-04 criteria re-checked on a locked build (scratch scripts `v04x/acc.mjs` 48/48, `v04x/axe.mjs`). Fixes

### R10 · WP-06 (FYI, done on the chrome side): film readout in Info
The real player plays the film from a `blob:` URL, so `video.currentSrc` no longer names the variant. Info now reads
`debugFilm.plan.variant` / `.tier` first (as `src/film/player/mount.ts` publishes them) and falls back to matching the
source; frame = `round(currentTime × fps)` of that variant, shown only for the `video` tier. Verified: `sd · f 141/480`
under SwiftShader. Keep `debugFilm.plan.variant` named after the `film-manifest` variant keys (`hd` / `sd` / `portrait`).

### R11 · WP-09 / WP-10: `SealImpression.rotation` is in radians
The compositor rotates the seal impression by `seal.rotation` radians (three.js convention). A value beyond ±45° is
taken as degrees and converted, so a degree value does not spin the seal upside down, but please pass radians.

### R12 · WP-05: crest orientation
The doc bar, the CV and today's print draw WP-02's `crest.svg` / `crest.json` — 丸に三つ組子 with the triangle pointing
**down** (▽). The cover still shows the WP-00 stub crest pointing up (△). When the cover's compass construction lands,
it must build the same ▽ figure, or the site shows two different crests.
