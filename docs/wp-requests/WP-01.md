## R1 · WP-08 / WP-11: localized tool names (`toolLabels`)
Appendix A types `Tool.name` as one string, so names like "Accessibility", "Incident command", "SLOs and error
budgets" or "AWS (multi-region)" would stay English on ja/zh pages. `src/content/facts.ts` now has an extra named
export (types.ts unchanged):

```ts
import { toolLabels } from '../../content/facts';   // render modules only (SSG, Node-safe)
toolLabels[tool.id][rc.lang]   // e.g. a11y → アクセシビリティ / Accessibility / 无障碍
```

- Use it for every visible tool name: the skills list rows, the stack-diagram labels (`skills/diagram.ts`), the
  print/CV stylesheet's skills line, `aria-describedby` readouts.
- Product names are identical in all three languages (Go, Kafka, PostgreSQL …).
- `toolLabels` is **not** part of `Content`, so it is not in the per-language runtime bundle. Runtime code
  (`index.ts`, `view.ts`) must read the label from the server-rendered DOM (e.g. a `data-label` attribute on
  the row), never import `src/content`.
