  addition to the 300 % IntersectionObserver and the idle prefetch.

## R7 · WP-00 / WP-11 (core/frame.ts): a frame request made during a tick forks a second rAF chain
`FrameLoop.tick` sets `rafId = 0` first; a callback that calls `frame.request()` or `frame.add()` during the
tick (e.g. ScrollTrigger's onUpdate running inside `lenis.raf()`, the chrome's `coalesce()` → `frame.add`, a
stage `resume()`) then schedules a rAF because `rafId` is 0, and the end of the tick schedules another one and
overwrites `rafId`. Both fire next frame; while scrolling this repeats, so several chains run in parallel
(measured on the road film before the workaround: 7 752 controller ticks in one 22 s scrub, against 196 after
it, with Lenis and ScrollTrigger stepped several times per rendered frame). Idle still reaches zero rAF.
Suggested fix (one line each): track `inTick` and let `request()` only set `requested = true` while it is
true, or end the tick with `if (!this.rafId && (more || this.requested)) this.rafId = requestAnimationFrame(this.tick)`.
Road works around it locally: its ScrollTrigger callbacks and the player's `kick()` run in a microtask after
the tick (src/sections/road/index.ts, src/film/player/scroll-film.ts); other sections and the chrome are
still affected until frame.ts is fixed.

## R8 · WP-11 / WP-04 / WP-00 (page-level scroll cost measured during the film)
Full page on `vite build` output, SwiftShader, `?film=hd&tier=static`, wheel scrub through the film:
main thread 27 % (no throttle) / 73 % (4× throttle); the film's own JS (controller + section) is 0.1 % / 2.7 %
of it, and the player alone on a bare page with the same file is 4 % / 26 % (native seek path + a 60 Hz frame).
The rest is page-wide: a CPU profile at 4× shows ScrollTrigger's scroll getter (`pageYOffset` reads that force
style/layout after Lenis' `scrollTo`) ≈ 1.0 s per 12 s, the chrome rulers' two `getBoundingClientRect()` per
frame after DOM writes and the `--mono-wdth` custom-property writes (10 Hz) → 424 layouts / 781 style recalcs in
one scrub, plus commit/paint of a ~5 000-node page. Fixing R7 and batching the ruler reads before writes are the
biggest wins; nothing in the road section forces layout per frame (verified with a getBoundingClientRect /
offset* / getComputedStyle hook).
